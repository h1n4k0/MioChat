# 使用指南

## 连接与操作

服务默认监听 `127.0.0.1:2222`。远程服务按需设置 `-listen :2222`，客户端连接示例：

```sh
ssh -t -p 2222 chat@example.com
```

登录和注册表单用闪动的 `>` 标出当前输入框。Tab、Shift+Tab 或鼠标切换焦点；关闭动画时提示保持常亮。

终端显示范围为 20–320 列、10–120 行，超出时安全截断；完整界面仍建议至少 40×24。阅读历史时内存窗口有界，旧消息继续保存在数据库。

| 操作 | 入口 |
| --- | --- |
| 命令、通知、联系人、功能菜单 | F1、F2、F3、F4 |
| 管理面板 | F8，需要相应权限 |
| 翻页、回到最新消息 | 滚轮 / PgUp / PgDn、Ctrl+End |
| 显隐侧栏、返回、退出 | Ctrl+B、Esc、Ctrl+C |
| @ 用户 | 右键用户名，或 `/mention 用户` |
| 指定回复 | 右键消息，或 `/reply 编号` |
| 戳一戳 | 双击用户名，或 `/poke 用户` |
| 消息操作菜单 | 左键消息 |

输入 `/help` 可搜索全部命令。若客户端把右键当作粘贴，可开启应用鼠标报告或使用命令入口。

向下滚动可连续加载后续记录；发送当前会话的消息、按 Ctrl+End 或使用 `/history` 可回到最新。

多设备同时编辑同一对话草稿时，会提示保留本机或加载其它设备；`/draft-conflicts` 可找回本人的冲突稿。长帖和画板固定原频道，失去权限或自动换房后会冻结发布，不会改发到大厅。

## 设备密钥

每个账号可绑定 10 把有效密钥，最多同时登录 3 个会话。支持 Ed25519、ECDSA P-256/P-384/P-521，以及 2048–8192 位 RSA；RSA 签名使用 SHA-2。

在自己的设备生成密钥，建议设置私钥口令；已有密钥可直接使用。示例：

```sh
ssh-keygen -t ed25519
ssh -t -p 2222 -i ~/.ssh/id_ed25519 -o IdentitiesOnly=yes chat@example.com
```

也可用 `ssh-keygen -t ecdsa -b 256` 或 `ssh-keygen -t rsa -b 3072`，连接时选择对应私钥路径。

首次携带未绑定密钥连接，先用聊天室账号密码登录，再确认绑定当前设备的指纹和名称。之后使用这把密钥连接会直接进入其所属账号。服务器不接收私钥。

`/keys` 管理设备；`/key-add` 绑定当前连接的公钥；`/key-rename 编号 名称` 重命名；`/key-remove 编号` 确认撤销。撤销会断开该密钥的登录会话，其它密钥和密码会话继续保留。

没有密钥时可勾选“不再提醒”，用 `/pref key_reminder on` 恢复。绑定只接受本次连接已经验证持有的公钥，不能粘贴任意公钥直接激活。密码验证过期后，绑定需要再次确认当前密码。

未携带密钥时，SSH 使用零问题 `keyboard-interactive` 打开账号密码界面。程序客户端需要支持此认证方式。登录后没有输入空闲或总在线时长限制；网络失联的连接仍会回收。

## 服务与数据

Linux 可使用 [systemd 单元](../deploy/miochat.service)，按实际路径和端口调整，并使用独立低权限账户运行。先注册聊天室账号，再在停服时授予站长权限：

```sh
./miochat -state /var/lib/miochat -owner 用户名
```

状态目录中的数据库和主机密钥应一起备份。一致性备份包含已提交的 WAL，目标目录必须不存在：

```sh
./miochat -state /var/lib/miochat -backup /var/backups/miochat/snapshot
```

检查及恢复需要停止对应实例；恢复前会另存当前状态。

```sh
./miochat -state /var/lib/miochat -check
./miochat -state /var/lib/miochat -restore /var/backups/miochat/snapshot
```

聊天室内的 `/backup`、`/check` 在后台执行，同一实例一次一个维护作业；`/canceljob` 可取消本连接的作业。备份会先检查空间，不会自动删除历史。恢复中断后，程序会在独占打开状态目录时完成已提交的恢复；应保留恢复标记和暂存文件。

消息、修订和审计不自动按时间或数量删除，应持续备份并监控磁盘。SSH 保护传输，密码使用 Argon2id；消息存于 SQLite，授权管理员可审计撤回内容，服务器管理员可读取数据，不提供端到端加密。
